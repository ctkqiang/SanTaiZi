三太子 SanTaiZi

一个用 Go 编写的模块化网络安全框架。控制台动态发现模块，模块在独立进程中执行， 通过一套很小的 SDK 把安全能力接入统一的操作界面。

适合授权渗透测试、安全教学、内部工具整合与模块化 PoC 管理。 默认中文界面，支持 Termux、macOS、Linux；核心模块不依赖外部运行时。

设计目标

让“写一个安全模块”变成一件小事：实现三个方法，编译成独立二进制，框架自动发现。

能力

它能做什么

三太子不是“一个大而全的扫描器”，而是一个把模块、控制台和执行边界组织起来的框架。

01

动态模块发现

框架递归扫描模块目录，只加载可执行文件，通过 --info 读取元数据，不需要重新编译框架。

02

独立进程执行

每个模块是独立二进制。模块崩溃不会拖垮控制台，参数通过 key=value 传入，结果从标准输出返回。

03

msfconsole 风格控制台

搜索、选择、查看选项、设置参数、运行、返回。支持 Tab 补全、历史、光标移动、中文/英文界面与窄终端布局。

04

Go 原生构建与安装

go build、go install、make install 都可以。模块不需要额外运行时、解释器或 SaaS 依赖。

05

内置实战模块

PHP2Shell 被动 triage、向量数据库只读评估、ESP WiFi 测试、MongoDB 内存泄露提取，四个方向开箱可用。

06

跨平台与 Termux

macOS / Linux / Windows 可构建；Termux 自动切换 ASCII 横幅、纵向模块列表与纵向选项，手机终端也能读。

边界说明

三太子是授权测试工具，不是权限许可。使用前必须确认目标范围、规则与法律边界。框架提供进程隔离与安全扩展点，但不等于完整沙箱；生产环境仍建议配合容器、最小权限账户与网络隔离。

工作原理

框架是怎么跑起来的

核心只有三件事：发现模块、读取元数据、在独立进程中执行模块。没有复杂的插件 ABI，也没有必须链接的运行时。

控制台internal/structure
→
注册表Registry
←
加载器ModuleLoader
→
模块二进制--info / --execute

启动阶段

  1. 确定目录：读取 SANTAIZI_MODULES_DIR；未设置时使用 ./modules。
  2. 递归扫描：filepath.Walk 遍历目录，只处理有可执行权限的文件，跳过名为 santaizi 的主程序。
  3. 元数据握手：执行 <module> --info，解析 name:、description:、cnvd:、cve: 和 option: 行。
  4. 登记：Loader 把路径、名称、描述、类型、选项写入 Registry，控制台通过它搜索和访问模块。

执行阶段

  1. 选择模块：use <索引|名称> 设置当前模块并初始化默认选项。
  2. 配置：set / setg 写入配置；控制台检查必填项。
  3. 执行：Loader 运行 <module> --execute key=value …，模块的 Init 接收参数，Run 执行逻辑。
  4. 回传：模块把报告写到标准输出；非零退出或 error: 前缀会被框架识别为失败。

命令行契约

接口方向格式说明
--info框架 → 模块标准输出文本模块被加载时调用；必须只输出元数据，不发起网络请求。
--execute框架 → 模块key=value运行模块；多个选项作为多个参数传入，值可以包含 =（按第一个 = 拆分）。
标准输出模块 → 框架纯文本报告显示在控制台“结果”区域；模块也可以输出多行文本。
标准错误模块 → 终端（直接运行时）警告/横幅授权提示、调试信息写 stderr。注意：框架执行时只回传 stdout；希望框架用户看到的声明应同时写入报告。
error: 前缀模块 → 框架error:消息执行失败时使用；Loader 会把它转换成框架错误。
为什么是独立进程？

模块可以用不同依赖、不同并发模型，甚至不同语言实现（只要遵守 CLI 契约）。框架不需要把第三方代码链接进主程序；模块崩溃、泄漏或死循环的爆炸半径也更小。代价是每次执行都有进程启动成本，且模块之间不能直接共享内存。

运行环境

模块进程继承框架启动时的工作目录，不会自动切换到模块目录；output=leak.bin 这样的相对路径会落在启动框架的目录。每次 run 都会启动新进程，Init 中的状态不会跨次保留。需要稳定位置时使用绝对路径或显式目录选项。

技术视角

控制台通过 Registry 查询模块，通过 Loader 执行模块。Loader 不解析模块内部实现，只遵守 CLI 协议。模块的“类型”取名称前三个字符（例如 php2shell → php、vecmap → vec），用于展示，不参与调度。

选项在控制台侧保存为字符串映射；Loader 拼成 key=value 参数。SDK 的 RunModule 用 flag 解析 --info / --execute，再把选项交给模块。

开发者视角

你写一个 package main，实现 sdk.Module 的三个方法，嵌入 sdk.BaseModule，在 main 里调用 sdk.RunModule。然后编译成可执行文件放进模块目录，框架就能发现它。

不要把模块链接进框架，也不要导入 internal/*。模块与框架之间只通过 SDK 和 CLI 契约通信。

SDK / API

模块作者应该使用哪些 API

唯一需要导入的包是 santaizi/sdk。不要把 internal/core、internal/structure 当成模块 API；它们是框架内部实现，可能变化。

核心接口

type Module interface {
    Info() ModuleConfig
    Init(options map[string]string) error
    Run() (string, error)
}

Info()

返回静态元数据。控制台和加载器会在加载阶段调用。这里不要发起网络请求、不要读大文件，也不要依赖运行环境。

  • Name：模块名，建议小写加下划线。
  • Description：一行说明，中文或英文都可以。
  • Options：参数定义。
  • CNVD / CVE：有编号就填写。

Init()

接收框架传入的选项，负责校验和设置默认值。SDK 不会自动把 Info 里的 Default 注入到 Config，所以你要自己合并默认值。

  • 先构造默认配置，再覆盖传入值。
  • 校验必填项、URL、端口、路径。
  • 不要在这里执行攻击性动作。
  • 返回错误会让框架停止执行 Run。

Run()

真正的工作在这里。返回一个可直接给用户阅读的报告字符串；失败返回 error。

  • 使用 context 和超时。
  • 限制响应体、记录数量和并发。
  • 不要 panic，不要 os.Exit。
  • 不要执行目标返回的指令，不要把目标数据当命令。

sdk.RunModule()

模块入口。main 里固定写：

func main() {
    sdk.RunModule(&MyModule{})
}

它负责解析 --info 和 --execute，打印模块信息或调用 Init / Run。

数据结构

type ModuleConfig struct {
    Name        string
    Description string
    Options     []Option
    CNVD        string
    CVE         string
}

type Option struct {
    Name     string
    Type     string   // string / int / bool
    Required bool
    Default  string
}

type BaseModule struct {
    Config map[string]string
}

func (b *BaseModule) GetOption(name string) string
默认值与必填项

Info().Options[].Default 只是展示给控制台的元数据，不会自动写入 Config。模块必须在 Init 中设置默认值。SDK 也不会强制 Required；控制台会检查，但独立运行 --execute 时必须由模块自己校验。

API 使用边界

可以使用不要使用原因
sdk.Module自己发明新的模块接口框架只认识这一个契约。
sdk.BaseModule / GetOption复制一套配置解析器保持选项行为一致。
sdk.ModuleConfig / sdk.Option用匿名 map 返回元数据Loader 依赖固定字段。
sdk.RunModule自己解析 --info / --execute避免与框架的 CLI 契约分叉。
标准库internal/core / internal/structure内部包不是稳定 API，且模块是独立进程。

选项类型

类型控制台表现模块侧处理
string原样保存校验空值、URL、路径、长度。
int控制台提示必须是整数用 strconv.Atoi 再校验范围。
bool接受 true/false/yes/no/on/off统一转成 true / false 后判断。

内置模块

内置模块

四个新模块覆盖 Web、向量数据库、无线和 MongoDB 四个方向。它们同时也是可以阅读的示例代码。

php2shell

Web / PHP

PHP2Shell 漏洞类的被动暴露分析。根路径 + 随机 canary，检测 soft-404、登录墙、限流、PHP 版本、SAPI、WAF/CDN。

  • target：PHP 端点 URL
  • scope / require_scope：授权范围门控
  • exploit：POC 门控，默认关闭
./modules/bin/php2shell --execute \
  target=https://example.com/index.php \
  scope=bug-bounty-2026 \
  require_scope=true

仅 GET；上游 POST/multipart POC 未移植，不会自动触发。

vecmap

向量数据库

Qdrant、Milvus、Weaviate、Chroma、Redis、Elasticsearch、OpenSearch、pgvector、Typesense、Pinecone、Vespa 的只读攻击面评估。

  • target：URL / 域名 / IP / CIDR
  • adapter：默认 auto
  • deep：有界记录抽样
  • evidence_dir：SQLite WAL 证据目录
./modules/bin/vecmap --execute \
  target=http://127.0.0.1:6333 \
  adapter=auto deep=true \
  evidence_dir=./evidence

硬拒绝 /management/stop、/delete、/drop、/upsert 等破坏性路径。

wifisec

无线 / ESP

ESP8266/ESP32 协处理器上的 WiFi 扫描、802.11 deauth 帧构造与注入、串口诊断。主机不需要 root。

  • serial_port：串口设备
  • ssid / bssid：目标选择
  • action：scan / deauth / diagnose
./modules/bin/wifisec --execute \
  serial_port=/dev/ttyUSB0 \
  action=scan

deauth 前打印完整法律红线；原生串口路径支持 macOS/Linux。

cve_2025_14847

MongoDB

MongoDB zlib 堆内存泄露提取。连接、发送构造的 OP_COMPRESSED 请求、捕获返回的堆字节，并做脱敏凭据模式匹配。

  • target：host:port / mongodb://
  • output：默认 leak.bin
  • safe_mode：默认 true，限制在 4 KiB
./modules/bin/cve_2025_14847 --execute \
  target=127.0.0.1:27017 \
  output=leak.bin safe_mode=true

仅提取；不会验证、重放、填充或使用泄露到的凭据。

Termux

Termux / 窄终端

界面会按终端宽度自动切换，不要求手机横屏。Termux 通过 TERMUX_VERSION / PREFIX 自动识别，即使宽度大于 90 列也使用纵向列表。

安装与构建

pkg install golang git make
git clone https://github.com/ctkqiang/SanTaiZi.git
cd SanTaiZi
make santaizi
./santaizi

没有 make 时：

go build -o santaizi ./framework
./santaizi

窄终端布局

  • 非 Termux 且 ≥ 96 列：ANSI Shadow 横幅 + 宽模块表格（最多 100 列）
  • 非 Termux 且 90–95 列：ANSI 横幅 + 宽选项表格，模块仍为纵向列表
  • Termux（任意宽度）或 48–89 列：ASCII 横幅 + 纵向模块/选项列表
  • < 48 列：紧凑横幅
  • 超长 CVE、描述与选项值按终端宽度换行；模块名过长时截断

Termux 额外键：Tab 补全；方向键历史/光标；音量键 + 字母发送 Ctrl 组合键。

贡献

如何参与贡献

你不需要先读完整个引擎。贡献可以从文档、测试、一个小模块或一个 bug 修复开始。原则是：改动小、边界清楚、可复现、可审查。

1选一个切入点文档 / 测试 / 小模块 / bug
2Fork + 分支feat/、fix/、docs/
3实现 + 自测build / vet / test / lint
4提交 PR说明动机、证据、风险
5评审与合并小步迭代

第 1 步：准备环境

git clone https://github.com/ctkqiang/SanTaiZi.git
cd SanTaiZi

go version        # Go 1.25+
make test         # go test ./...
make vet          # go vet framework + internal/structure + sdk + modules
make lint         # 可选，需要 golangci-lint v2.x

第 2 步：Fork 并创建分支

git checkout -b feat/module-example-http

# 或者
git checkout -b fix/console-search-index
git checkout -b docs/termux-guide

第 3 步：遵守代码约定

必须

  • gofmt 格式化；遵循 Go 习惯。
  • 错误用 fmt.Errorf("...: %w", err) 包装。
  • 网络请求设置超时、限制响应大小。
  • 目标数据视为不可信输入，做清洗与截断。
  • 模块只导入 santaizi/sdk 和标准库（或已存在的依赖）。
  • 新增模块要有 --info / --execute 冒烟测试。

避免

  • 不要修改 internal/、sdk/ 来“适配”单个模块。
  • 不要 panic、os.Exit 或无限重试。
  • 不要默认执行破坏性动作；危险能力必须显式开启。
  • 不要把密钥、Cookie、Token 写进日志或报告。
  • 不要在一个 PR 里混合无关重构。

从零写一个模块

下面实现一个最小但完整的模块：对目标 URL 发一次 GET，输出状态码、Content-Type 和页面标题。它演示了元数据、默认值、授权横幅、超时、响应限制、错误处理和 main 入口。

先确认授权

示例会访问目标。请只对你拥有或获得明确书面授权的系统运行。模块里不要默认执行攻击、写入、删除或认证尝试。

第 1 步：创建目录

mkdir -p modules/example_http
$EDITOR modules/example_http/main.go

第 2 步：完整代码

package main

import (
    "context"
    "fmt"
    "io"
    "net/http"
    "os"
    "regexp"
    "strconv"
    "strings"
    "time"

    "santaizi/sdk"
)

var _ sdk.Module = (*ExampleHTTPModule)(nil)

var titleRE = regexp.MustCompile(`(?is)<title[^>]*>(.*?)</title>`)

type ExampleHTTPModule struct {
    sdk.BaseModule
}

func (m *ExampleHTTPModule) Info() sdk.ModuleConfig {
    return sdk.ModuleConfig{
        Name:        "example_http",
        Description: "只读 HTTP 头部分析示例模块。",
        Options: []sdk.Option{
            {Name: "target", Type: "string", Required: true, Default: ""},
            {Name: "timeout", Type: "int", Required: false, Default: "8"},
        },
    }
}

func (m *ExampleHTTPModule) Init(options map[string]string) error {
    m.Config = map[string]string{
        "target":  "",
        "timeout": "8",
    }
    for key, value := range options {
        m.Config[key] = value
    }

    _, _ = fmt.Fprintln(os.Stderr,
        "AUTHORIZED TESTING ONLY: example_http sends one GET request. Confirm written authorization first.")

    target := strings.TrimSpace(m.GetOption("target"))
    if target == "" {
        return fmt.Errorf("example_http: option \"target\" is required")
    }
    if !strings.HasPrefix(target, "http://") && !strings.HasPrefix(target, "https://") {
        return fmt.Errorf("example_http: target must start with http:// or https://")
    }
    m.Config["target"] = target

    timeout, err := strconv.Atoi(m.GetOption("timeout"))
    if err != nil || timeout < 1 || timeout > 60 {
        return fmt.Errorf("example_http: timeout must be an integer between 1 and 60")
    }
    return nil
}

func (m *ExampleHTTPModule) Run() (string, error) {
    timeout, _ := strconv.Atoi(m.GetOption("timeout"))
    ctx, cancel := context.WithTimeout(context.Background(), time.Duration(timeout)*time.Second)
    defer cancel()

    request, err := http.NewRequestWithContext(ctx, http.MethodGet, m.GetOption("target"), http.NoBody)
    if err != nil {
        return "", fmt.Errorf("example_http: build request: %w", err)
    }
    request.Header.Set("User-Agent", "SanTaiZi-example_http/1.0 (authorized testing)")
    request.Header.Set("Accept", "text/html,application/xhtml+xml")

    response, err := http.DefaultClient.Do(request)
    if err != nil {
        return "", fmt.Errorf("example_http: request failed: %w", err)
    }
    defer func() {
        _ = response.Body.Close()
    }()

    body, err := io.ReadAll(io.LimitReader(response.Body, 64*1024))
    if err != nil {
        return "", fmt.Errorf("example_http: read body: %w", err)
    }

    title := ""
    if match := titleRE.FindSubmatch(body); len(match) == 2 {
        title = strings.TrimSpace(string(match[1]))
        if len(title) > 120 {
            title = title[:120]
        }
    }
    if title == "" {
        title = "(no title)"
    }

    return fmt.Sprintf(
        "example_http — READ-ONLY HTTP PROBE\nTarget: %s\nStatus: %d\nContent-Type: %s\nTitle: %s\n",
        m.GetOption("target"),
        response.StatusCode,
        response.Header.Get("Content-Type"),
        title,
    ), nil
}

func main() {
    sdk.RunModule(&ExampleHTTPModule{})
}

这段代码在做什么

  1. Info 声明名称、描述、选项和默认值。
  2. Init 先设置默认值，再合并框架传入的选项；校验 target 和 timeout。
  3. Run 使用带超时的 context 发一次 GET，限制读取 64 KiB。
  4. 输出纯文本报告；失败返回 error，不 panic。
  5. main 调用 sdk.RunModule，由 SDK 处理 --info / --execute。

为什么这样写

  • 不依赖内部引擎：模块可以单独复制、单独编译。
  • 默认值显式：SDK 不注入 Info 默认值，Init 必须自己合并。
  • 失败可读：错误带模块名前缀和上下文。
  • 有边界：一次请求、超时、响应上限，避免误伤。
  • 输出稳定：结果写 stdout；调试与横幅写 stderr。需要框架用户看到的声明请同时写进报告。

把纯逻辑拆成小函数，用 go test 覆盖边界。例如把 target 校验拆成 validateTarget，然后写表驱动测试：

package main

import "testing"

func TestValidateTarget(t *testing.T) {
    tests := []struct {
        name    string
        target  string
        wantErr bool
    }{
        {"https", "https://example.com/", false},
        {"http", "http://127.0.0.1:8080/", false},
        {"missing scheme", "example.com", true},
        {"empty", "", true},
    }
    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            if err := validateTarget(tt.target); (err != nil) != tt.wantErr {
                t.Fatalf("validateTarget(%q) error = %v, wantErr %v", tt.target, err, tt.wantErr)
            }
        })
    }
}

真实提交里请把示例中的校验逻辑抽成 validateTarget 再测试。测试不应访问外网。

安全

安全与合规

三太子面向授权测试。模块作者对模块行为负责；框架提供执行边界，但不替代授权、法律判断和客户沟通。

授权先行

确认书面授权、目标范围、时间窗口、速率限制和禁止动作。没有授权就不要运行任何网络模块。

默认只读

新模块应默认只读。需要写入、删除、重启、认证尝试或高并发的能力必须显式选项开启，并在文档里警告。

输入与输出

目标返回的 header/body 是不可信数据：限制大小、清洗控制字符、处理 bidi/ANSI，避免把目标内容当命令执行。

敏感数据

报告与证据中脱敏 Cookie、Authorization、API Key、Token、密码。原始泄露数据单独存放并设置 0600 权限。

资源边界

设置请求超时、最大响应体、最大记录数、并发上限。不要无限重试或扫描无边界 CIDR。

进程隔离

框架用独立进程执行模块；但 internal/security 目前只是扩展点。生产环境请结合容器、低权限用户、网络策略和审计。

漏洞披露

发现框架或内置模块的安全问题，请不要在公开 Issue 里贴可直接利用的细节。优先使用仓库 Security 页面的 GitHub Security Advisory，或先联系维护者确认私密渠道。

常见问题

常见问题

模块加载不出来 / all 是空的

确认 SANTAIZI_MODULES_DIR 指向包含可执行文件的目录；检查二进制是否有执行权限（chmod +x）；运行 ./modules/bin/模块名 --info 看是否输出合法元数据。

为什么 ./santaizi 还是旧界面？

执行 ./santaizi -V，必须显示 三太子 v1.2.0。如果是旧版本，在仓库根目录运行 make santaizi，并关闭仍在运行的旧进程。

go install 安装到哪里？

不设置 GOBIN 时安装到 $(go env GOPATH)/bin；设置 GOBIN="$PWD/modules/bin" 时直接安装到框架模块目录。当前 go.mod 的模块路径是 santaizi，请在仓库检出目录内执行 go install ./modules/...。

模块执行失败，如何让框架识别错误？

在 Init 或 Run 返回 error；SDK 会输出 error:... 并以非零状态退出。不要在模块里直接 os.Exit(0) 掩盖失败。

为什么控制台的索引和全局模块 ID 不一样？

search / all 显示的是相对索引，use 0 指向最后一次列表的第 0 项。这样搜索结果可以直接选择，不需要记全局 ID。

Termux 里表格还是溢出？

确认运行 v1.2.0；该版本在 Termux 或窄终端使用纵向列表，并把宽表格限制在 100 列。仍异常时用 ./santaizi -V 确认版本，并检查终端宽度。

可以提交带攻击性的模块吗？

可以讨论，但必须默认关闭危险能力、要求明确授权范围、提供安全说明和影响范围，并遵守当地法律。维护者可以拒绝高风险的默认行为。
